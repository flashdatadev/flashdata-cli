# Security

[FlashData](https://flashdata.dev) · [API documentation](https://flashdata.dev/docs)

Read the [storage and threat model](docs/security.md). Never put API keys, proofs, signed URLs or customer-storage secrets into issue reports. Use the private support channel available from your FlashData account. No security-report email address is invented here.

Default tests use dummy keys and local mock servers. Do not run undocumented live onboarding or paid calls while debugging. Preserve uncertain run records and original credential stores; deleting them is not a safe authentication repair.
